# 知识库：上传、检索与关联智能体

上传成功只是开始。资料需要解析、分块并能被检索，最后关联到正在使用的智能体，才能在对话中发挥作用。

## 准备工作 {#scope}

本页面向[用户控制台知识库](https://xiaozhi.me/console/knowledge-base)，与商家开发者平台的企业知识库分开。准备一份结构清晰、允许提供给服务处理的资料，先用小样本测试。

当前上传界面接受 PDF、DOCX、XLSX/XLS、PPTX/PPT、Markdown、TXT、CSV、HTML、EPUB 等类型；格式被接受不代表其中图片、复杂表格或扫描文字一定能正确解析。具体限制以页面与解析结果为准。

## 1. 创建并上传 {#upload}

1. 新建知识库，使用能辨认主题的名称。
2. 在文档页上传资料并填写文档名称，按页面提供的解析方式提交。
3. 等待解析结束，检查状态和错误，不把“文件已上传”当作“知识已经可检索”。

用户账号与 GitHub 认证账号的库数、每库文档数存在差异，当前代码按角色区分 1/10。额度以自己的页面提示为准，原教程的所有账号 1 库 1 文档并非统一上限。

## 2. 检查分块 {#chunks}

进入文档分块页，查看标题、段落、表格和数字是否保留正确语义。重点检查：

- 扫描 PDF 是否取得正文，图片中的说明是否遗漏。
- 表格行列、单位、日期和否定语句有没有拆错。
- 页眉页脚、目录或无关文字是否反复干扰检索。
- 关键答案是否跨块断开，是否需要调整源文档或编辑块。

修正后重新测试，不用增加更多重复文档掩盖错误解析。

## 3. 做召回测试 {#recall}

用准备好的问题执行召回测试，先看返回片段是否直接支持答案。包括一个应能回答的问题、一个换种说法的问题、一个资料里没有答案的问题。

召回为空：先检查解析、提问用词和资料是否真的包含答案。召回错误：检查文档质量、分块和相似无关内容。不要一开始就将问题归因于模型。

## 4. 关联到智能体 {#associate}

打开目标智能体配置，按当前扩展能力/知识库选项关联并保存。确认自己测试的设备和智能体一致，再用相同问题进行真实对话。旧版界面的 MCP 工具开关位置不作为当前唯一入口。

## 怎么确认完成 {#verify}

解析成功，召回测试命中正确片段，智能体已保存关联；真实对话能依据资料回答，资料没有的内容不会被误认为已经收录。必要时核对对话里的工具调用记录。
