# 首页语言判断修复 · 2026-11-14

问题：中文读者从正式域名根入口进入英文。旧实现只检查 `navigator.languages[0]`，并将任何语言页面访问写入同一个持久偏好；一旦自动进入英文，后续根入口继续优先读取该值。根页面依赖 Vue 挂载后跳转，跳转前显示英文界面。官网和文档子域名的 localStorage 各自独立，不会自动共享语言选择。

修正：

- 初次访问检查完整浏览器语言列表，包含中文时优先中文；英文浏览器进入英文，无法匹配时使用中文。兼容简繁中文、地区后缀和下划线形式。
- 只记录桌面/手机语言菜单或根入口中明确选择的语言，不再将普通文章访问当成语言选择。
- 新增独立的手动选择存储键，忽略无法区分“自动访问”和“手动选择”的旧值；不修改用户的浏览器语言设置。
- 根页面在 head 中执行跳转，避免等待应用挂载时先显示英文；SPA 进入根页面时复用同一判断函数。明确的 `/zh/…` 和 `/en/…` 链接继续直接访问，保留查询参数和锚点。

验证：Node 的 6 组回归测试覆盖中文变体、中英文混合列表、英文浏览器、未支持语言、显式选择、旧英文自动记录、禁止存储及早期跳转脚本。Chrome 本地实测根入口进入中文；手动切英文后根入口仍进入英文；访问中文链接不会改写该选择；手动切回中文后再次进入根入口保持中文。文章正文、路径和英文翻译摘要均未改动。

`npm run check` 全部通过；另直接执行生产构建 HTML 中的 head 脚本，验证中英混合、仅英文及两种手动选择共 4 个情景，根 HTML 的 `lang` 为 `zh-CN`。正式域名部署结果以 GitHub Actions 及后续线上检查为准。
