# 首页语言判断修复 · 2026-11-14

起因与后续澄清：读者观察到浏览器界面是中文，但文档根入口进入英文；随后确认浏览器报告的语言为 `en-US`，首次进入英文符合其语言偏好。此前加入“列表只要包含中文就优先中文”的规则覆盖了用户顺序，现已撤回。旧实现将普通页面访问也写入持久偏好、根页等待 Vue 挂载后跳转的问题独立存在。官网和文档子域名的 localStorage 各自独立，不会自动共享语言选择。

修正：

- 初次访问按浏览器语言列表的偏好顺序采用首个支持的语言：`en-US, zh-CN` 进入英文，`zh-CN, en-US` 进入中文。只跳过暂不支持的语言，不对中文额外提权；全部无法匹配时使用站点默认中文。兼容简繁中文、地区后缀和下划线形式。
- 只记录桌面/手机语言菜单或根入口中明确选择的语言，不再将普通文章访问当成语言选择。
- 新增独立的手动选择存储键，忽略无法区分“自动访问”和“手动选择”的旧值；不修改用户的浏览器语言设置。
- 根页面在 head 中执行跳转，避免等待应用挂载时先显示英文；SPA 进入根页面时复用同一判断函数。明确的 `/zh/…` 和 `/en/…` 链接继续直接访问，保留查询参数和锚点。

验证：Node 的 6 组回归测试覆盖中文变体、两种中英文偏好顺序、跳过未支持语言后仍保持顺序、显式选择、旧英文自动记录、禁止存储及早期跳转脚本。上一轮 Chrome 的手动选择保留、跨语言文章访问不改写选择的验证继续适用；此前“首次中文”的观察对应已撤回的规则，不再作为现行自动语言判断的依据。文章正文、路径和英文翻译摘要均未改动。

`npm run check` 全部通过；另直接执行生产构建 HTML 中的 head 脚本，验证中英混合、仅英文及两种手动选择共 4 个情景，根 HTML 的 `lang` 为 `zh-CN`。正式域名部署结果以 GitHub Actions 及后续线上检查为准。
